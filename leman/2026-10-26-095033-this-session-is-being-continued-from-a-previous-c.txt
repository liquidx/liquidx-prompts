  The big discovery: there is no server-side thread store

  The gateway (version 0.18.0, model hermes-agent) is an OpenAI-compatible async
  agent-run runner, not a conversation store. What actually exists:

  ┌─────────────────────────────────┬───────────────────────────────────────┐
  │            Endpoint             │             What it does              │
  ├─────────────────────────────────┼───────────────────────────────────────┤
  │ GET /v1/health, /v1/models      │ probe + model list                    │
  ├─────────────────────────────────┼───────────────────────────────────────┤
  │ POST /v1/runs                   │ starts an async run → 202 {run_id,    │
  │                                 │ status:"started"}                     │
  ├─────────────────────────────────┼───────────────────────────────────────┤
  │ GET /v1/runs/{id}               │ poll status/output/usage              │
  ├─────────────────────────────────┼───────────────────────────────────────┤
  │ GET /v1/runs/{id}/events        │ SSE stream of the run                 │
  ├─────────────────────────────────┼───────────────────────────────────────┤
  │ POST /v1/chat/completions,      │ standard OpenAI, available but not    │
  │ /v1/responses                   │ the primary path                      │
  └─────────────────────────────────┴───────────────────────────────────────┘

  There is no /v1/threads, no global event feed, no run-list, no /openapi.json.
  I verified two behaviors that drove the redesign: input accepts a full
  messages array and the agent correctly recalls earlier turns from it, but
  session_id alone does not replay history. So conversation history is 
  client-managed, and the app is the system of record for threads.

  The run event stream uses a non-standard framing — data:-only frames with the
  event type inside the JSON (message.delta, reasoning.available,
  tool.started/tool.completed, run.completed), no id:/retry: lines. That means
  no Last-Event-ID resume; instead a re-opened stream replays from the start
  (which conveniently also lets an old thread lazily re-fetch its trace).
